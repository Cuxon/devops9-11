# Учебное развёртывание сервера

## 10. Ansible

Проект находится в `practice-11/ansible/`. Управляющий узел — macOS с Ansible, управляемый — Ubuntu 24.04 в Multipass. Закрытые ключи и пароли не хранятся в репозитории.

Inventory `bootstrap.ini` использует student и первоначальный доступ; `prod.ini` — devops, порт 22 и локальный ключ `~/.ssh/devops_vm`. Адрес VM нужно уточнить после восстановления снимка. Публичный ключ читается lookup на управляющем узле, закрытый ключ на VM не передаётся.

Роли: base устанавливает базовые зависимости и Docker из официального репозитория; ssh настраивает пользователя, ключ, sudo, SSH и UFW; nginx настраивает reverse proxy с проверкой перед reload; app сначала загружает образ, затем изменяет контейнер и проверяет /health.

Образ: `ghcr.io/cuxon/devops9-11`. Проверенный полный SHA: `002a84b6702f4aef06e31f8b8518cc265d0e186b`. Приложение слушает 5000 в контейнере; на VM порт 5000 привязан только к 127.0.0.1. Внешний HTTP идёт через Nginx на 80. Ожидаемый ответ /health — HTTP 200 и JSON `{"status":"ok"}`.

Все команды выполняются из `practice-11/ansible/`:

```sh
ansible-playbook -i inventory/bootstrap.ini site.yml --ask-pass --ask-become-pass
ansible-playbook site.yml
ansible-playbook verify.yml
```

Если bootstrap выполнен по заранее установленному публичному ключу, применяется inventory с ключом и только --ask-become-pass. Повторный site.yml и read-only verify.yml должны давать changed=0. При негативном аудите остановленный контейнер восстанавливается основным site.yml.

`force_handlers = True` гарантирует выполнение уже уведомлённых обработчиков при ошибке последующей задачи. Порядок pull → container сохраняет прежний контейнер, если новый тег не существует. Это не универсальная гарантия отсутствия простоя при любой ошибке.

У пользователя devops предусмотрен учебный NOPASSWD sudo. В Multipass в AllowUsers дополнительно оставлен ubuntu для управления VM. Пакет GHCR публичный, поэтому секрет чтения не нужен.
