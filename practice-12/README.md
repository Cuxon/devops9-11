# Практическая работа №12 / Контрольная работа №3

Автоматический деплой связывает приложение `practice-10/`, публикацию GHCR
и Ansible-проект `practice-11/ansible/`. Код предыдущих работ используется
на месте, без второй копии Ansible и без изменения `group_vars/all.yml`.

## Последовательность

`lint → test → image → deploy` в `.github/workflows/ci.yml`.
Первые три задания выполняются на GitHub-hosted Ubuntu; deploy — на
управляющем Mac с self-hosted runner и дополнительной меткой `devops-vm`.
Deploy разрешён только для `push` в `main` после успешного image.
Для PR и workflow_dispatch он пропускается.

Runner использует существующие окружение `~/.venvs/devops11`, коллекции Ansible,
ключ `~/.ssh/devops_vm` и проверенные host keys из known_hosts.
Регистрационный токен runner, закрытые ключи и пароли в Git не помещаются.
Для публичного репозитория необходимо обязательное одобрение запусков
от всех внешних участников. Запуски чужих PR на этом runner не одобряются.
После занятия runner останавливается, если больше не нужен.

## Версия и проверка

Image публикует тег полного `GITHUB_SHA`. Deploy передаёт этот же SHA через
`-e "app_tag=${GITHUB_SHA}"` в site.yml и verify.yml. Значение из extra vars
имеет приоритет над сохранённым тегом практической №11.
Ручной запуск site.yml без `-e` выбрал бы старый тег из group_vars;
для выполнения заданий этой работы ручной деплой не применяется.

`concurrency: deploy-devops-vm`, `cancel-in-progress: false` исключают
одновременное выполнение двух деплоев и отмену начавшегося задания.
Ожидающее задание может быть заменено более новым.

Аудит проверяет SSH, точный тег, loopback-привязку контейнера и оба health.
Дополнительно curl с Mac проверяет `/health` через внешний адрес Nginx.
`--fail` обрабатывает HTTP-ошибки, таймауты ограничивают ожидание,
`pipefail` сохраняет отказ curl при передаче JSON в Python. Неверный JSON
или тело ответа также завершают job ошибкой.
Deploy имеет только `contents: read`; checkout не сохраняет токен Git.
Задание deploy не включается в обязательные проверки PR, поскольку там skipped.

## Задания и доказательства

1. PR с добавлением deploy: skipped в PR; успешный deploy после merge в main;
   PLAY RECAP, совпадение SHA запуска с тегом контейнера и ответ приложения.
2. Отдельный PR меняет версию в приложении и тесте на `1.1.0-tsukanov`.
   После автоматического deploy фиксируются ответы до/после, изменившиеся
   задачи и время от merge до завершения deploy.
3. Отдельный PR с `git revert` отменяет изменение версии. Новый выпуск
   снова возвращает `1.0.0`, но имеет новый SHA.

Для заданий 1–3 запрещены ручные изменения сервера и локальный запуск
ansible-playbook. Read-only SSH для docker inspect разрешён.
Откат VM на снимок не используется.

Статус: задание deploy подготовлено; его запуск и следующие два PR
ещё не выполнены. Фактические результаты сохраняются в локальном отчёте.
